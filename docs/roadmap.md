# HostShell 产品路线图

> 状态：规划建议，待产品范围确认  
> 更新日期：2026-11-02  
> 依据：当前仓库结构、`README.md`、`prd.md`、`REGRESSION.md`，以及终端设置和 AI 助手参考截图。

## 1. 路线图目标

HostShell 的主线是让运维人员能够安全、可靠地从移动设备连接服务器，并在连接失败或网络变化时看清状态、恢复工作。路线按“连接可验收 → 终端体验完善 → AI 辅助 → 高级能力扩展”推进。

截图用于提供产品能力参考，不代表所有选项已经定稿。截图中的具体默认值，例如 1000 行缓冲区、30 秒心跳和 12 步工具上限，均作为候选值，需经过产品与实现评估。

## 2. 当前项目基线与范围假设

- 仓库包含 Rust SSH 核心、CLI、macOS SwiftUI 客户端和 iOS SwiftUI 客户端。
- README 列出的连接与认证能力包括直连、ProxyJump、多跳中继、Cloudflare Access、ProxyCommand、密码/私钥/SSH Agent，以及 SSH 配置导入。
- 本次实现范围扩展为 SSH 隧道：本地 TCP/Unix socket 转发、SOCKS5 DynamicForward、TCP/Unix socket RemoteForward；真实环境验收仍需执行。
- 回归文档说明，自动化构建和离线测试无法证明真实凭据、堡垒机、Cloudflare Access 和远端终端的端到端行为；发布前仍需专用环境验证。
- PRD 的目标平台包括 iOS 和 Android，但当前仓库没有 Android 客户端工程。本路线暂按 **iOS 为移动端主线、macOS 为配套客户端、CLI 为开发与运维入口** 规划；Android 是否纳入需要单独决策和估算。
- 当前工作区存在未提交改动。路线图不把这些改动视为已合并或已验收的功能。

## 3. 里程碑

### M0：连接稳定性与发布验收基线（P0，先行）

**目标：** 确认现有 SSH 能力在目标客户端和真实测试环境中形成可复现的连接闭环。

**工作项：**

1. 建立按客户端、认证方式和代理模式划分的验收矩阵：直连、单跳/多跳 ProxyJump、Cloudflare Service Token、ProxyCommand、密码/私钥/SSH Agent；并覆盖本地 TCP/Unix socket、SOCKS5 和 RemoteForward。
2. 验收 Host Key 首次信任、变更拦截、各跳独立认证、连接取消和资源清理。
3. 验收连接阶段及错误分类，覆盖 DNS/网络、代理或跳板、网关鉴权、SSH 握手、用户认证和终端启动。
4. 在隔离测试环境验证窗口尺寸同步、键盘输入、终端输出和常见交互程序。
5. 将自动化回归结果与真实网络验收结果分别记录；不以本地构建通过代替线上链路验收。

**完成标准：**

- 支持范围内的连接方式都有明确的测试记录和负责人。
- 连接失败能呈现失败阶段、用户可读原因和下一步操作。
- 取消连接后资源可回收；凭据、Token 和 Cookie 不进入日志。
- PRD 中的连接成功率和失败阶段可诊断率目标具备可采集、可核对的口径。

### M1：移动终端体验与可配置设置（P1）

**目标：** 让用户能按设备和工作习惯调整终端，并在移动网络中更容易继续会话。

**工作项：**

1. 终端外观：字号档位、可用等宽字体、配色主题、光标样式、终端仿真类型。
2. 会话参数：滚动缓冲区大小、SSH 心跳间隔，以及清晰的默认值和边界校验。
3. 输入效率：可配置键盘辅助栏和快捷键；覆盖 Esc、Tab、方向键、Ctrl/Alt 组合及用户常用按键。
4. 连接恢复：前后台切换和网络变化时显示准确状态；提供明确的重连操作，并保留本地终端历史和滚动位置。
5. iOS 与 macOS 共用设置模型和持久化语义，界面交互按平台调整。

**完成标准：**

- 用户设置重启应用后仍然生效；不支持的系统字体有合理回退。
- 键盘辅助键在 shell、vim 和 tmux 常见场景可用。
- 旋转、键盘弹出和窗口变化后，远端终端尺寸正确更新。
- 断线、重连中和恢复成功状态有清晰区分；不承诺 iOS 后台永久保活。

**截图参考项：** 简体中文、终端字号、配色、JetBrains Mono 等字体选项、方块光标、xterm-256color、1000 行缓冲区、30 秒心跳、键盘自定义和快捷键栏。数值与选项以设备能力及验证结果为准。

### M2：终端 AI 助手（P1，依赖 M0 的稳定会话）

**目标：** 为终端操作提供解释、错误分析和建议，减少用户查阅资料与排障的往返。

**工作项：**

1. 在移动端会话提供可开关的 AI 入口和总开关。
2. 支持解释命令、分析错误输出、给出可执行建议。
3. 允许用户控制是否附带终端上下文；默认关闭自动附带，调用前展示将发送的内容范围。
4. 提供模型提供商和模型选择；连接提供商后可刷新模型列表。
5. 提供工具调用摘要显示开关和工具步数上限；截图中的 12 步可作为初始候选值。
6. 记录必要的调用状态与结果，避免把密码、私钥、Token、Cookie 和不相关终端历史发送给模型。

**安全边界与完成标准：**

- 首期以解释、分析和建议为主；任何会改变远端状态的命令执行都必须由用户明确确认。
- 用户可以在发送前检查和编辑上下文，并能随时关闭 AI 功能。
- AI 提供商错误、超时和上下文过长时有明确提示，不影响 SSH 会话本身。
- 不向用户展示隐藏的内部推理；可提供简明结论、引用的终端片段和工具执行摘要。

### M3：资产管理、安全与诊断完善（P1/P2）

**目标：** 降低配置维护成本，并提升日常运维中的可追溯性。

**工作项：**

1. 盘点已有 SSH 配置导入能力，补齐预览、冲突处理和不支持项提示。
2. 完善主机搜索、标签/分组、收藏和跳板机顺序管理。
3. 完善 known_hosts 查看、删除和逐跳校验界面。
4. 完善诊断日志导出、脱敏和清理流程。
5. 评估生物识别、应用锁及敏感操作二次确认。

**完成标准：**

- 导入前可预览新增与冲突项；无法识别的代理配置不会静默降级成直连。
- 删除信任记录、清除本地数据等高影响操作有明确确认步骤。
- 导出的诊断内容不包含凭据和终端输出，且需要用户主动触发。

### M4：高级连接能力与平台扩展（P2，单独立项）

**候选范围：** SFTP、多会话标签、团队资产同步、Android 客户端。

这些能力会增加文件权限、网络暴露、账户同步或平台维护成本，建议分别确认用户需求、安全边界、数据模型和维护投入后再纳入正式排期。

## 4. 推荐顺序

1. **先完成 M0**：对 README 和 PRD 声明的现有功能做清点和实测，修复阻断验收的问题。
2. **再推进 M1**：建立稳定、可恢复的会话与设置基础，并落实终端外观和输入效率。
3. **随后推进 M2**：在会话状态和脱敏边界明确后加入 AI，先交付只读分析，再评估远端工具执行。
4. **并行梳理 M3**：对已有导入、密钥和诊断实现先做差距盘点，再补齐缺口。
5. **最后评估 M4**：基于使用反馈拆分独立项目，不与首期连接稳定性目标混排。

## 5. 建议追踪的产品指标

PRD 中已有初始目标，可在 M0 明确采集口径，并用隔离测试或用户主动反馈验证：

- 直连、ProxyJump、Cloudflare Access 各自的连接成功率。
- 连接失败阶段可诊断率与各阶段耗时。
- 断线检测时间、重连成功率和本地历史保留情况。
- 崩溃率及终端大输出时的内存稳定性。
- AI 功能使用率、用户采纳建议比例及误操作反馈；不采集主机地址、用户名或终端内容作为产品埋点。

## 6. 需要确认的产品决策

1. 首个正式发布平台是否确定为 iOS，macOS 的定位是正式客户端还是开发者配套工具？
2. Android 是否进入近期目标？若进入，需建立 Android 客户端并单独估算。
3. AI 功能首期是否仅限解释与建议？若允许工具执行，哪些命令需要强制确认？
4. 字体、主题、缓冲区、心跳间隔和工具步数的默认值及可选范围是什么？
5. 是否在 M0 为 Cloudflare Service Token、Web SSO 和自定义 ProxyCommand 分别定义支持级别？
